# 电视图片方向处理功能说明

> 文档版本：v1.0
>
> 更新日期：2026-09-30
>
> 适用入口：用户端 `http://120.79.131.180:8080/`，管理后台 `http://120.79.131.180:8082/admin`

## 1. 功能目标

电视照片可能存在 90°、180° 或 270° 方向错误。方向错误会影响屏损位置、裂纹方向和天侧/地侧的判断。系统现支持两种处理模式，由管理员全局选择：

| 模式 | 处理方式 | 适用场景 |
|---|---|---|
| 自动旋转 | EXIF 归一化 → OpenCV 几何检测 → A/B 候选图 → 多模态复核 → 结果融合 | 优先减少用户操作，网络和模型服务稳定时使用 |
| 用户手动调整 | 跳过 OpenCV 与方向多模态请求，逐张由用户选择旋转角度 | 对分析速度要求高，或外部模型网络不稳定时使用 |

系统默认为“自动旋转”，避免升级后改变已有用户流程。

## 2. 管理后台配置

进入：

`管理后台 → 模型配置 → 大模型配置 → 前端分析面板控制 → 上传图片方向处理`

可选项：

- **自动旋转（OpenCV + 多模态复核）**
- **用户手动调整（跳过自动检测）**

选择后点击“保存配置”即可生效。用户端每次开始鉴定前都会重新读取配置，因此已经打开的用户页面也能获取最新模式，通常无需刷新。

对应配置字段：

```json
{
  "orientationMode": "auto"
}
```

- `auto`：自动旋转。
- `manual`：用户手动调整。
- 非法值会被后端拒绝；历史配置中没有该字段时按 `auto` 处理。

## 3. 自动旋转流程

### 3.1 EXIF 与预处理

首先根据图片 EXIF Orientation 纠正像素方向，再统一转换为 JPEG，避免后续环节对手机旋转标记理解不一致。

### 3.2 OpenCV 几何检测

OpenCV 用于确定电视长轴方向和基础旋转角度：

1. 执行 Canny 边缘检测。
2. 使用标准形态学闭运算连接断裂边缘。
3. 标准检测不足时，使用更大核的自适应闭运算兜底。
4. 同时支持透视四边形，适配斜拍后的梯形或平行四边形电视边框。
5. 电视只拍到局部、缺少一两个角时，可根据 Hough 直线族推断局部边框，但会限制几何置信度。
6. 使用原始边缘支撑率、面积比、长宽比和几何质量过滤假候选框。

OpenCV 能较好地处理 90°/270° 的横竖方向，但仅凭几何边框很难判断横向电视是否上下倒置。

### 3.3 A/B 候选图

为判断 180° 倒置，系统生成两张候选图：

- **候选 A**：按 OpenCV 得到的基础角度旋转。
- **候选 B**：在同一张原图上按“基础角度 + 180°”旋转。

两张候选图均限制在 1024×1024 以内，使用 JPEG 75% 质量，以减少请求体积和网络中断概率。A/B 是二选一比较，比让通用模型直接完成 0°/90°/180°/270° 四分类更稳定。

### 3.4 多模态复核

多模态模型对比 A/B，重点观察：

1. 较宽的电视下边框。
2. 地板、桌面、墙面和其他环境物体。
3. 底座、支架、指示灯。
4. 电视侧边的品牌 Logo 或文字。

当前自动链路中 OCR 默认关闭，代码仍保留用于调试；显式开启时的可靠阈值为 `0.80`。多模态自动采信阈值为 `0.76`，几何检测可靠阈值为 `0.62`。

### 3.5 结果融合与人工确认

以下情况会进入用户方向确认：

- 未检测到足够可靠的电视几何区域。
- 多模态返回 `uncertain` 或置信度未达阈值。
- 多模态服务不可用，且没有其他可靠方向证据。
- 显式启用 OCR 后，OCR 与多模态的高置信度结果冲突。
- OpenCV 方向服务调用失败。

人工确认时，用户可以左转 90°、翻转 180°、右转 90°，再点击“方向正确，继续”。用户确认的方向优先级最高，后续损伤分析不再覆盖。

## 4. 用户手动调整流程

当后台设置为 `manual` 时：

1. 用户正常拍照或上传 1—5 张图片。
2. 用户点击“鉴定分析”。
3. 系统不调用 `/api/knowledge/orient-images`，也不生成 A/B 候选图。
4. 页面按上传顺序逐张弹出“调整电视机方向”，显示“当前序号/图片总数”。
5. 用户可选择左转 90°、翻转 180°或右转 90°；无需旋转时直接确认。
6. 只有所有图片都完成人工确认后，系统才会进入损伤分析；任意一张取消都会中止本次鉴定。
7. 页面将每张图的确认角度写入实际图片像素，然后添加取证水印并开始损伤分析。

手动模式只跳过“图片方向识别”，不会跳过屏损鉴定、RAG 检索或 LLM 损伤分析。

## 5. 方向调试页面

管理员可访问：

`http://120.79.131.180:8082/admin/tv-orient`

页面支持选择文件、拖拽和 `Ctrl+V` 粘贴图片，并展示：

- 原图、OpenCV 检测过程、旋转结果。
- Canny 边缘绿线、候选框黄线、最终选择红线、局部直线蓝线。
- 透视四边形、局部边线推断和候选框评分。
- 几何置信度、方向来源、多模态选择与人工确认状态。

调试进度共分为 10 个阶段：

1. 图片预处理
2. OpenCV 总流程
3. Canny
4. 闭运算/轮廓
5. 候选框
6. OCR
7. 生成 A/B
8. 多模态
9. 结果融合
10. 旋转输出

### 计时口径

- **OpenCV 总流程**：实时增长，记录 Node.js 调用 Python 服务的端到端时间，包含 IPC、图片传输与解码、Canny、闭运算和几何检测。
- **Canny / 闭运算 / 候选框**：Python 返回后显示 OpenCV 内部精确耗时，不会把整个服务等待时间误计为 Canny 耗时。
- **总耗时**：从创建检测任务到输出最终结果的端到端时间。

OpenCV 总流程是父阶段，Canny、闭运算和候选框是其内部子阶段，不应将四者直接相加。

## 6. 外部模型网络异常

对 `ECONNRESET`、`ETIMEDOUT`、`UND_ERR_SOCKET` 等临时网络错误，以及 HTTP 408、429、500、502、503、504，方向多模态请求最多尝试 4 次，间隔约为 1、2、4 秒并附加小幅随机抖动。重试范围覆盖响应体读取，可处理收到响应头后连接中断的情况。

重试仍失败时：

- 调试页明确显示“模型服务不可用”，不再伪装成“选择 uncertain，置信度 0%”。
- 自动流程保持安全降级，在没有其他可靠证据时要求用户确认方向。
- 如外部模型服务长期不稳定，可在管理后台切换为“用户手动调整”。

- `POST /api/admin/debug/tv-orient-job`：管理后台对外提供的调试任务代理接口；内部转发到 `POST /api/debug/tv-orient-job`。

## 8. 验收要点

### 自动模式

- 横拍正常电视不应被误转 90°。
- 竖拍电视应能归一到横向。
- 180° 倒置图应由 A/B 多模态比较判断；证据不足时必须人工确认。
- 透视斜拍和局部电视图应显示相应候选线框，但低几何置信度不得直接自动采信。
- 模型网络失败时不得显示为 0% 置信度的正常判断。

### 手动模式

- 开始鉴定后应立即进入第 1 张图的方向调整，不应出现 OpenCV 或生成 A/B 的等待。
- 多张图应逐张确认，上一张确认后再显示下一张。
- 直接确认应保持 0°；旋转后提交的实际像素方向应与预览一致。
- 取消方向确认应中止本次损伤分析。

## 9. 运维注意事项

- 切换模式只影响之后开始的鉴定任务，不会修改历史图片和鉴定记录。
- 手动模式依赖用户正确确认方向，一线人员应优先根据底座、指示灯、Logo、文字和环境上下关系判断。
- 自动模式的多模态判断会增加等待时间和模型调用成本；手动模式用户操作更多，但方向处理时间更可控。
- 修改相关代码后至少执行 Node.js 语法检查、方向融合单测、配置安全单测和 `git diff --check`。
