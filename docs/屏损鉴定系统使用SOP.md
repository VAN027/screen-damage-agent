# 屏损故障鉴定系统一线人员使用 SOP

> 文档版本：v2.0
> 适用系统：屏损故障鉴定 v5.2
> 更新日期：2026-08-20
> 适用对象：门店、售后网点及上门服务的一线鉴定人员

## 1. 使用目的与基本原则

本系统用于现场拍照取证、屏损特征分析、规则判定和相似案例查询，帮助一线人员形成标准化的初步鉴定记录。

系统结果是辅助意见，不替代公司最终审核。遇到“转人工复核”、证据不足、现场事实与系统结果明显冲突或客户存在争议时，不得仅凭系统结果对客户承诺退换货、保修、赔付或责任归属，必须按现行业务流程转交人工审核。

## 2. 正式入口

一线人员使用手机或电脑浏览器打开：

**http://120.79.131.180:8080/**

使用要求：

- 建议使用最新版 Chrome、Edge 或手机系统浏览器。
- 保持网络稳定，鉴定期间不要切换网络或关闭页面。
- 页面无需输入管理员令牌；如页面要求输入后台管理令牌，说明进入了错误入口。
- 当前入口为 HTTP 地址，部分手机浏览器会限制网页直接调用摄像头。出现此情况时，使用“系统相机拍照”或“上传相册”即可，不影响鉴定。

## 3. 鉴定前准备

开始前确认：

- 已核实设备、客户工单和现场机器为同一对象。
- 擦净手机镜头，现场光线充足，避免强反光、逆光和手部遮挡。
- 屏幕表面如有保护膜，不得为拍照擅自撕除；应在备注或现场记录中说明。
- 如需上传客户设备照片和位置，应按现场业务要求完成告知或授权。
- 不得使用其他机器、历史工单、网络下载或经过美化处理的图片代替现场照片。

## 4. 标准操作流程

### 第一步：进入拍照取证页

1. 打开正式入口，确认页面标题为“屏损故障鉴定”，版本为 v5.2。
2. 如需网页相机，点击“同意并授权”，按浏览器提示允许摄像头和位置信息。
3. 如不同意授权或浏览器不支持网页相机，选择“系统相机拍照”或“上传相册”。

### 第二步：拍摄或上传照片

系统支持 1—5 张照片。建议拍摄 3 张：

1. **整机全景**：完整显示整块屏幕及设备外观。
2. **损伤近景**：清楚显示裂纹、撞击点、漏液、熔屏或异常区域。
3. **辅助证据**：根据现场情况拍摄屏幕侧角、包装破损或其他相关痕迹。

拍照要求：

- 损伤区域清晰对焦，不能过暗、模糊或被反光遮挡。
- 近景照片仍应保留足够边界，便于判断损伤位置和形态。
- 多张照片必须属于同一台设备。
- 系统会对照片压缩并添加时间、位置等取证水印。
- 缩略图左上角标有“主”的照片为主图；应确保主图最能代表本次屏损特征。
- 拍错可删除单张；全部不合格时点击“重拍全部”。

### 第三步：填写安装与故障信息

上传第一张照片后，系统会打开“安装与故障信息”。必须按现场事实选择，不得直接沿用默认值。

| 字段 | 可选内容 | 填写要求 |
|---|---|---|
| 安装状态 | 未安装 / 已安装 / 不确定 | 以鉴定当时的实际状态为准 |
| 开箱人员 | TCL 授权人员 / 非授权人员 / 不清楚 | 未安装场景下重点核实 |
| 包装箱状态 | 无破损 / 有破损 / 无法查看 | 应与包装现场照片或记录一致 |

填写完成后点击“确认信息”。确实无法核实的项目选择“不确定”“不清楚”或“无法查看”，禁止为了获得某种结论而猜填。

### 第四步：启动鉴定分析

1. 确认照片和现场信息无误。
2. 点击“鉴定分析”。
3. 页面显示分析进度时耐心等待，不要连续点击、刷新页面或重复上传。
4. 通常几十秒内返回结果；图片较多或网络较慢时可能需要约 2 分钟。
5. 分析完成后，系统会继续生成规则判定和相似案例，请等待结果区域完整显示。

### 第五步：核对结果

重点核对以下内容：

- 屏损位置、屏损形态、故障原理和故障环节是否与照片一致。
- 鉴定结论是否为“质量问题”“非质量问题”“屏幕完好”或“转人工复核”。
- 判定卡片中的 Case 编号和规则版本是否正常显示。
- 判定路径中的安装、开箱和包装信息是否与现场填写一致。
- 相似案例是否与本机损伤特征具有可比性。

必须转人工复核的情况：

- 系统明确显示“转人工复核”。
- 照片无法清楚展示损伤，或多张照片疑似不是同一台机器。
- 两项及以上关键信息无法确认。
- 系统识别的位置、形态或结论与现场观察明显不符。
- 相似案例与本机特征差异明显。
- 涉及重大客诉、批量异常、人员安全或高额赔付。

### 第六步：提交准确性反馈

完整判定后，页面会显示“本次判定是否准确”。每单都应反馈：

#### 判定准确

1. 点击“✓ 判定正确”。
2. 按钮显示“✓ 已确认”后，反馈才算提交成功。

#### 判定有误

1. 点击“✗ 判定有误”。
2. 在“问题反馈”中选择正确的鉴定结论。
3. 在问题备注中写明错误点和现场依据，例如：“系统判为非质量问题，现场可见屏内无外力点、裂纹由边缘自然延伸，建议复核为质量问题”。
4. 点击“确认提交”。
5. 页面显示“✓ 已提交审核”后完成。

纠错提交后只会进入待审核队列，不会立即修改案例库或训练数据。不得为了测试重复提交；如提示“已在待审核队列中”，无需再次操作。

### 第七步：开始下一单

完成本单并记录 Case 编号后，点击“重拍全部”清除本次照片、结果和反馈状态，再开始下一台设备。不得在同一页面状态下混用两台设备的照片。

## 5. 结果使用规范

- 对客沟通应使用“系统初步鉴定”“建议人工复核”等规范表述。
- 不得把 AI 分析文字单独当作最终责任认定。
- 不得隐瞒与系统结论冲突的现场证据。
- Case 编号应记录到对应工单，便于后台追溯。
- 客户照片、设备信息和位置数据仅用于本次业务，不得转发到个人群聊或无关平台。

## 6. 常见异常处理

| 页面现象 | 一线处理方法 |
|---|---|
| 摄像头未启用或无法授权 | 使用“系统相机拍照”或“上传相册” |
| 上传后图片模糊、方向错误 | 删除该图后重新拍摄；必要时在原图预览中检查方向 |
| 提示“图片加载失败” | 删除异常照片，重新拍照或从相册重新选择 |
| 提示“网络连接异常”或 `fetch failed` | 确认网络正常，等待 30 秒后点击重试；不要连续重复点击 |
| 分析超过 2 分钟无进展 | 截图当前页面，刷新后重新上传；仍失败则上报技术支持 |
| 提示“判定请求失败” | 点击页面中的“重试”；仍失败时记录错误文字和发生时间并上报 |
| 相似案例为空 | 不影响查看本次初步结果，但不得自行引用无关案例 |
| 反馈按钮未出现或提示“反馈会话尚未就绪” | 等待结果全部加载；仍未出现则重新执行本次鉴定 |
| 纠错提示缺少图片、位置或形态 | 换用清晰完整照片重新执行鉴定 |
| 页面空白或样式异常 | 强制刷新页面；电脑按 `Ctrl+F5`，手机关闭页面后重新打开 |

上报技术支持时提供：发生时间、使用入口、页面错误原文、截图、网络类型、是否可重新进入页面，以及 Case 编号（如已生成）。不要在群聊中发送客户敏感照片或任何后台令牌。

## 7. 一线人员快速检查表

提交分析前：

- [ ] 照片属于同一台设备，主图清晰。
- [ ] 已包含全景和损伤近景，必要时有辅助证据图。
- [ ] 安装、开箱、包装信息均按现场事实填写。
- [ ] 不确定项没有猜填。

结束本单前：

- [ ] 已核对位置、形态、结论和判定路径。
- [ ] 需要人工复核的案例已转交，不对客作最终承诺。
- [ ] 已点击“判定正确”或按实际情况提交纠错审核。
- [ ] 已将 Case 编号记录到对应工单。
- [ ] 开始下一单前已点击“重拍全部”。
