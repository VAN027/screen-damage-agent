# 屏损故障鉴定智能体 — 系统使用 SOP

> 版本：v1.0 ｜ 适用系统版本：v5.1 ｜ 更新：2026-08-04
>
> 本文档是系统的标准操作流程（SOP），面向两类角色：
> - **一线售后人员**：使用手机 H5 端完成现场鉴定取证与判定
> - **系统管理员/导师**：使用管理后台维护案例库、模型配置与规则

---

## 一、系统入口与角色

| 角色 | 入口 | 用途 |
|------|------|------|
| 一线售后人员 | `http://<服务器IP>:8080/`（手机浏览器） | 现场鉴定：拍照取证 → 信息录入 → 查看判定结果 |
| 管理员/导师 | `http://<服务器IP>:8082/admin` | 案例库管理、快速标注、模型配置、规则管理、索引维护 |

> 生产环境通常通过 Nginx 域名反代，实际地址以公司发布为准。

## 二、一线售后人员操作 SOP（H5 端）

### 2.1 操作流程总览

```
① 现场拍照取证  →  ② 填写安装与故障信息  →  ③ 提交判定  →  ④ 查看结果与纠错
```

### 2.2 分步操作说明

#### 第 1 步：现场拍照取证

1. 用手机浏览器打开系统地址，进入「① 现场拍照取证」页面。
2. 点击 **同意并授权**，授权「摄像头」与「位置信息」（用于记录拍照地点，形成取证证据）。
3. 对准屏幕损伤位置拍照，注意：
   - 系统会自动添加 **时间戳水印**，请勿遮挡损伤区域。
   - 拍摄微距损伤时，可点击 **⊕ 微距辅助线** 按钮，将损伤点对齐虚线框，确保对焦清晰。
4. 支持多种取证方式（任选其一）：
   - **拍照**：调用后置摄像头拍摄
   - **上传相册**：从手机相册选择现场照片（可多选）
   - **粘贴图片**：支持 Ctrl+V 粘贴截图或图片链接
5. 拍照完成后可 **重拍全部** 重新取证。

> **取证规范（重要）**：
> - 至少 1 张包含损伤全貌的照片，损伤点需位于画面中心且对焦清晰。
> - 画面中避免出现无关遮挡物。
> - 若损伤为漏液/熔屏，需额外拍摄一张 **微距特写**（可开启辅助线）。

#### 第 2 步：填写安装与故障信息

点击「**安装与故障信息**」按钮，填写：

| 字段 | 选项 | 说明 |
|------|------|------|
| 安装状态 | 已安装 / 未安装 / 不确定 | 按现场实际情况选择 |
| 开箱人员 | TCL 授权人员开箱 / 非授权人员开箱 / 不清楚 | 仅当"未安装"时需要填写 |
| 包装箱状态 | 无破损 / 有破损 / 无法查看 | 判定责任归属的关键依据 |

点击「**确认信息**」保存。

#### 第 3 步：提交判定

1. 确认照片与信息填写完成后，点击「**提交判定 →**」按钮。
2. 系统自动执行：
   - **决策引擎**：按决策树判定责任归属并打分；
   - **图像检索**：比对历史案例库，推荐相似案例；
   - **LLM 鉴定**（可选）：流式生成鉴定报告。
3. 页面自动跳转至「② 判定结果」。

#### 第 4 步：查看判定结果

结果页包含以下内容：

| 区块 | 内容 | 说明 |
|------|------|------|
| 判定卡片 | 结论标题 + 图标 + Case 编号 + 规则版本 | 结论类型：产品质量问题 / 物流问题 / 非产品质量问题 / 需进一步鉴定 |
| 屏损概况 | 故障位置、故障形状、当前状态、初步鉴定结论 | 由图像分析 + 安装信息生成 |
| 判定路径回溯 | 决策树逐步问答记录 | 展示责任归属的推理链，供对客解释 |
| 相似案例 | Top5 相似历史案例 | 供现场比对参考 |

#### 第 5 步：纠正反馈（数据飞轮）

如认为分析结果不准确，点击「**分析不准？点此纠正 →**」：
1. 在纠正面板中修正各字段（屏损位置/形态/原理/环节/结论等）。
2. 点击「**确认提交并同步至案例库**」。
3. 纠正数据将自动沉淀为训练数据并同步至案例库，用于提升后续准确率。

> **收尾**：鉴定完成后点击「**鉴定新案例**」开始下一单。

## 三、管理员操作 SOP（管理后台）

后台包含 6 个页签：**规则集管理 / 案例库管理 / 模型配置 / 鉴定评估 / SQL 查询 / 仪表盘**。

### 3.1 案例库管理

#### 新增案例（单个）
1. 进入「案例库管理」页签。
2. 点击「新建案例」，填写标注字段（屏损位置/形态/环节/结论等，带 `*` 为必填）。
3. 上传案例图片，保存。
4. 系统自动提取图片特征并写入向量索引（无需手动训练）。

#### 批量导入 / 导出
1. 支持 JSON 批量导入与导出，用于案例库迁移与备份。
2. 导入后系统自动为每个案例建立向量索引。

#### 快速标注（⚡ 核心功能）

适用场景：批量导入大量现场图片，快速建立案例库。

```
拖拽/选择批量图片 → AI 批量预填 → 人工确认/修正 → 保存入库 → 自动建索引
```

操作步骤：
1. 在案例库管理中选择「快速标注」入口，**拖拽批量导入图片**。
2. 点击「**AI 批量预填**」：系统逐张调用 LLM 自动填写标注字段（带实时进度条）。
3. 逐张检查预填结果，修正不准确字段：
   - 标签按钮：点击选中，再次点击取消；
   - 文本域/输入框：直接修改。
4. 快捷键操作：`←` `→` 切换图片，`Enter` 下一张，`Esc` 退出标注。
5. 点击保存，图片入库并自动写入向量索引。

> **注意**：预填结果仅供参考，涉及责任判定的结论字段（鉴定结论/屏损环节）务必人工核实后确认。

### 3.2 模型配置

进入「模型配置」页签，可配置：

| 配置项 | 说明 | 建议 |
|--------|------|------|
| 主模型 | 鉴定报告用 LLM（API Key / Endpoint / 温度 / Max Token） | 使用强模型保证报告质量 |
| 系统提示词 | 鉴定指令，决定报告输出格式 | 优化提示词是提升准确率的关键手段 |
| 标注模型 | 快速标注专用 LLM（独立配置） | 可使用便宜模型降低标注成本 |
| 标注提示词 | 标注用系统级提示词 | 微调可提升 AI 预填准确率 |
| RAG 知识库 | 文档上传 / 检索配置 / 开关控制 | 上传故障原理类文档增强判定依据 |

配置后可用「**模型测试**」上传图片实时验证配置是否生效。

### 3.3 向量索引维护

- **一键重建向量索引**：当特征算法升级或索引异常时，在「向量检索」区域点击「重建向量库」。
- 监控 **向量服务状态 / CLIP 可用性**，确保检索链路正常。

### 3.4 规则管理

1. 进入「规则集管理」页签，可查看决策树节点与结论节点。
2. 创建/更新规则后需执行「**发布**」操作才生效（支持灰度发布，避免影响线上判定）。
3. 发布新规则前，建议在「鉴定评估」页签用历史案例回归验证，防止判定回退。

## 四、启动与运维 SOP

### 4.1 一键启动（开发环境）

```powershell
.\start.ps1   # 四个服务分窗口启动
```

### 4.2 分步启动（推荐调试）

启动顺序必须为：

```bash
# 终端 1 — Python 图像特征服务 :8084（必须最先启动）
python services/knowledge-ai/python/main.py

# 终端 2 — Node.js 知识库服务 :8083
node services/knowledge-ai/src/index.mjs

# 终端 3 — Node.js 管理中台 :8082
node services/decision-admin/src/index.mjs

# 终端 4 — Node.js BFF 网关 :8080（前端入口）
node services/gateway-bff/src/index.mjs

# 可选 — 决策引擎 :8081
node services/decision-engine/src/index.mjs
```

### 4.3 生产部署

```bash
# PM2 进程管理
pm2 start ecosystem.config.cjs

# 或 Docker 编排（5 个服务）
docker compose up -d
```

### 4.4 健康检查

| 服务 | 健康检查地址 |
|------|-------------|
| BFF 网关 | `http://localhost:8080/api/health` |
| 决策引擎 | `http://localhost:8081/api/health` |
| 管理中台 | `http://localhost:8082/api/health` |
| 知识库 | `http://localhost:8083/api/health` |
| Python 特征服务 | `http://localhost:8084/api/health` |

返回 `{"status":"ok"}` 即正常。

## 五、异常处理

| 现象 | 可能原因 | 处理方式 |
|------|---------|---------|
| H5 提示「判定请求失败」 | 后端服务未启动 / 网络异常 | 检查 4.4 各服务健康状态；等待 15 秒超时后自动重试 |
| 提示「无摄像头访问权限」 | 页面为 HTTP 连接或浏览器未授权 | 改用 HTTPS 访问，或使用「系统相机拍照/上传相册」 |
| 相似案例为空 | 案例库过少或向量索引未建立 | 扩充案例库；在后台执行「重建向量索引」 |
| LLM 分析无输出 | 模型配置未生效 / API Key 失效 | 检查「模型配置」→「模型测试」 |
| 判定结果异常 | 规则版本过旧 | 检查「规则集管理」是否发布新规则 |
