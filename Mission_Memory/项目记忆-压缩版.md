## 一、项目概述

- **用途**：TCL 一线售后人员使用的**电视屏幕故障智能鉴定系统**（v5.0+），手机 H5 完成「拍照取证 → 安装信息 → AI 分析（RAG+LLM 三模式）→ 判定结论」，并配套管理后台（案例库/评估/标注/配置）。
- **形态**：纯原生 JS 单页 H5 + Node.js 原生 http 微服务（无 npm 运行时依赖，`.mjs` 只用 `node:` 内置模块）+ Python 图像特征服务。非 Docker 部署，由 **PM2 + Nginx** 托管。

## 二、系统架构

```
用户(手机/浏览器) → Nginx :80 ─┬─ /            → gateway-bff :8080（前端H5 + API网关）
                               ├─ /admin /api/admin/* → decision-admin :8082（管理后台+代理）
                               └─ /api/knowledge/* → decision-admin :8082 → knowledge-ai :8083
```

| 服务 | 端口 | PM2 名 | 职责 |
|------|------|--------|------|
| gateway-bff | 8080 | screen-gateway-bff | 托管 frontend/index.html + 代理 `/api/v1/*`、`/api/knowledge/*`（SSE 用 pipeProxy 透传不缓冲） |
| decision-engine | 8081 | screen-decision-engine | 决策树判定 `/api/decision/evaluate`，result 只输出 3 种标准枚举 |
| decision-admin | 8082 | screen-decision-admin | 管理后台静态页 + `/api/admin/*` 规则管理 + `/api/knowledge/*` 通用代理（含 isStream 白名单 pipeProxy） |
| knowledge-ai | 8083 | screen-knowledge-ai | 核心后端：案例 CRUD、SQL 查询、评估、LLM 分析、field-defs、correction、备份 |
| python-features | 8084 | screen-python-features | FastAPI + **DINOv2 ViT-S/14 (384维)** 图像特征提取与向量检索（numpy-cosine 内存索引） |

- **启动**：`pm2 start ecosystem.config.cjs`（5 个 app）；`pm2 save` 已配置开机自启。重启服务器后 5 个服务自动恢复。
- **Nginx**：`nginx-site.conf`，`client_max_body_size 20m`；SSE 路由需 `proxy_buffering off`（analyze-llm-stream / eval/batch-analyze）。
- **服务依赖**：knowledge-ai 依赖 python-features(:8084)；decision-engine 依赖 decision-admin(启动时拉规则)。

## 三、核心功能清单

### 3.1 前端 H5（frontend/index.html，~2300行）
- 拍照授权弹窗（同意并授权=摄像头+位置，暂不使用=相册降级）；微距辅助线（默认显示+暗色蒙版+切换按钮）
- 图片前端压缩（长边 1024px，JPEG 0.75，水印含时间戳/位置）；相册上传；**Ctrl+V 粘贴图片或链接**（URL 走 fetch→Blob 避免 canvas 污染）
- 相机降级：`getUserMedia` 失败 → `<input capture="environment">` 调系统相机
- **三模式分析**（由后台 `panelConfig.analysisMode` 控制，前端无切换 UI）：hybrid（RAG+LLM 并行，LLM 带 RAG 上下文）/ rag（仅向量检索 Top-K 聚合）/ llm（纯大模型）
- 判定结果页：result-card（仅 3 种标准结论）、RAG 报告、LLM 流式输出、Top5 相似案例（含缩略图+点击放大）、返回按钮、**6 字段纠正面板**（提交→training 表+回写案例库+自动建案例）
- UI 主色 **TCL 红 `#e60012`**，全部界面无 emoji（已清除），简洁商务风
- `state.analysis`=RAG 结果、`state.llmResult`=LLM 结果，两条流水线独立；报告展示用 RAG 结果

### 3.2 管理后台（services/decision-admin/static/admin.html，~4400行）
- **Tab：规则集管理 / 案例库管理 / 模型配置 / 鉴定评估 / SQL 查询 / 仪表盘**
- 案例库：动态表单 `renderCaseForm()`（由 `currentAnnoFields` 驱动，增删字段/顺序/多图上传 `imageDataList`）、图片入库批量导入、快速标注（全屏 overlay + InteractivePreview 缩放/旋转/拖动/居中 + AI 分析此图 + AI 批量预填横幅+进度条 + 4 套主题切换 + 删除此图）、标注字段配置弹窗（可拖拽）、系统推荐结论 `autoSuggestResult`（按形态+环节查历史统计）、齿轮菜单收纳低频操作
- 鉴定评估：创建批次/上传图片、批量 LLM 分析（SSE 进度条+中断按钮）、6 字段（状态观察/位置/形态/原理/环节/结论）✅❌ 判断、详情面板（上一条/下一条+键盘快捷键）、同步到案例库/删除选中（批量勾选+Shift/Ctrl 多选）、判别人（多人协作+5s 轮询）、导出 Excel（含图片+汇总分析 Sheet）
- SQL 查询：左侧数据库目录树（展开列/双击插入列名）+ 7 个快捷模板 + 执行查询 + 下载 xlsx
- 仪表盘：6 张卡片（案例库/训练数据/知识库/图片存储/向量服务/服务状态）
- 模型配置：大模型配置（含 systemPrompt、测试连接）、标注模型配置（独立 API Key + 独立 systemPrompt + **分析模式下拉**）、知识库管理、向量检索服务（DINOv2 状态/重建索引/备份数据库按钮 `/api/admin/backup`）

### 3.3 后端 knowledge-ai
- **field-defs.json 是字段唯一事实来源**（6 个鉴定字段的 label/type/required/options/mapping/cssClass/icon/stageConsequenceMapping），前后端全部动态读取，改一处全局生效
- 案例库 SQLite `knowledge.db`：`cases` / `training` / `evaluations` 三表，WAL 模式，better-sqlite3
- LLM 分析：`analyzeWithLLM`(非流式60s→300s超时) / `analyzeWithLLMStream`(SSE)；`buildPrompt()` 有自定义 systemPrompt 时**完全放权给 systemPrompt 自由输出**（不再强制 JSON），靠 `extractJSON` 三层兜底（JSON块→文本关键词→正则）解析
- 标注：`annotateSingle`/`annotateBatch`，`annotateImageByMode` 按 hybrid/llm/rag 分发
- 评估：eval/create、upload-images、batch-analyze(SSE)、save、stats、sync-to-cases、clean-orphans、export-xlsx（含图片+汇总Sheet+最终采用列）
- SQL：sql-schema / sql-query / sql-query/export（仅 SELECT 白名单，5000 行上限，exceljs 导出）
- 其他：correction（纠正闭环）、backup（VACUUM INTO，存 `data/backup/`）、dashboard、field-defs、model-config、annotation-config、rebuild-index

## 五、数据层要点

- **cases 表**：id(TEXT PK), title, deviceModel, symptoms(JSON), crackShape(JSON数组), crackLocation, crackStage, crackPrinciple, result, resultLabel, images(JSON数组), corrections(JSON), needsReview, created_at, updated_at 等
- **crackShape 是多值数组**：存 `["点放射状屏裂"]`；匹配用 `arrayOverlap`（部分匹配按比例得分）；LLM 输出逗号分隔自动拆数组；序列化自动兼容旧单值字符串
- **result 枚举（3 种）**：`product_quality_issue` / `not_product_quality` / `no_damage`（屏幕完好）；`logistics_issue`、`needs_further_review` 已从全系统移除
- **evaluations 表**：llm_* / human_* / match_*(0=错 1=对 -1=未标) / rag_location / rag_shape / match_rag_* / judged_by / analyzed
- **training 表**：features(JSON) + 6 个纠正字段 + original* 字段 + source(manual_correction) + imageBase64 + caseId
- 旧 JSON 文件 `cases.json`/`training.json` 已迁移 SQLite（保留不删，仅历史参考）；`model-config.json`/`annotation-config.json` 含 API Key，已被 .gitignore 排除

## 六、重要修复与经验（避坑）

### 前端通用
- `esc()` 只接受字符串：多值数组渲染前必须规范化（`Array.isArray(v) ? v.join('、') : v`），否则 `(s||"").replace is not a function` 抛错且被 try/catch 吞掉 → 表现为"点了没反应"（案例打不开即此因，已修复）
- 静态页修改**无需重启服务**（每次从磁盘读，带 no-cache），浏览器强刷即可；后端 `.mjs` 修改需 `pm2 restart screen-knowledge-ai`
- **忘记重启 = 最常见"改动没生效"原因**：改完代码先 `pm2 restart` 再排查

### LLM 调用
- `normalizeEndpoint` 自动拼 `/chat/completions`：识别任意 `/v1`、`/v3` 版本段，剥离误填的 `/responses` 后缀（豆包 Ark 用 `/api/v3/chat/completions`）；已同时加固 llm-analyzer.mjs 和 knowledge-base.mjs
- **豆包/推理模型很慢**（doubao-seed-2-1-pro 实测 125s+）：超时已提到 300s；嫌慢可换 `doubao-1.5-vision-pro`
- 自定义 systemPrompt：作为 `role:system` 发送；`buildPrompt` 检测到 systemPrompt 非空时让模型自由输出（不再强 JSON），靠 extractJSON 兜底
- LLM 输出字段名可能不一致（中文键"位置/形态/原理/环节/结论"、Markdown `**字段**：`）：extractAnnotationJSON 做了中英文键映射 + Markdown 规范化
- eval batch-analyze 正则曾因"屏损*"旧术语匹配不到"故障*"新术语导致字段为空——统一术语后已修复

### SSE / 代理
- **SSE 必须三层都透传**：Nginx `proxy_buffering off` → decision-admin 的 `isStream` 白名单 `pipeProxy` → knowledge-ai SSE handler；走 `fetchJson` 会把整个流缓冲住（表现为"一直卡在准备分析/进度条不动"）
- decision-admin `isStream` 白名单包含：`images`、`analyze-llm-stream`、`eval/batch-analyze`、`eval/export-xlsx`、`sql-query/export`；新增二进制/流式路由时**必须同步加白名单**
- `pipeProxy` 需透传 `Content-Disposition`（否则下载文件名丢失）

### 图片方向
- 上传入库链路：`autoOrientImage`(EXIF, sharp) → `autoOrientTV`(边缘密度分析：竖版rot90 + 底/顶边框与logo加权判断 flip180)
- `autoOrientTV` 检测 TV 区域覆盖图 >92% 时跳过旋转（局部特写不旋转）
- LLM 分析前（llm-analyzer 的 `_autoOrientDataUrl`）也会调用 `autoOrientTV` 纠方向
- 旧图批量纠偏工具：`services/knowledge-ai/tools/fix-image-orientation.mjs`

### 向量/重建索引
- **python-features 被 pm2 delete 后要重新 `pm2 start ecosystem.config.cjs --only screen-python-features`**，并 `pm2 save`
- DINOv2 模型已缓存（`~/.cache/huggingface/hub/models--facebook--dinov2-small`），加载必须 `local_files_only=True`（HuggingFace 被墙，不带该参数会加载失败）
- **rebuildVectorIndex 传参 `crack_shape` 必须是字符串**：`Array.isArray(c.crackShape) ? c.crackShape.join(',') : c.crackShape`（传数组 → pydantic 422 → 整批失败）
- 重建索引按 20 条一批防 OOM；Python 端 `_rebuild_index` 会清空重建内存索引

### 其他后端
- `backupDb` 用的是 `VACUUM INTO`，必须字符串拼接路径（better-sqlite3 不支持 `?` 占位符）；备份前先删同日期旧文件；`db` 未初始化时要先 `initDb()`（"DB not initialized"）
- `saveEvalAnnotation` 的 match 判断要用 `1===1` 而非 `true`（前端传整数）；动态 SQL 只更新传入字段（乐观锁）
- eval 批次删除后要重置 `sqlite_sequence`（否则 id 从 1812 起跳）
- 导出 xlsx 端点必须带 `Cache-Control: no-cache`（否则代理默认 24h 缓存导致数据过期）
- `model-config` / `annotation-config` 是独立的两个配置文件，互不影响
